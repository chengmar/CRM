# 外贸获客 Agent 使用说明

## 先看结论

截至 2026-07-26 18:06（北京时间），现有服务器已升级到 V23 企业收件箱范围修复版。企业邮箱、客户发现、官网邮箱取证、开发信、真实发送、回信监听、飞书客户管理同步和公网监测网站均已接通。V23 只更新了现有 VPS；面向全新环境的一键安装脚本按要求没有更新。

当前生产状态：

- 已形成 165 封可追踪开发信和 165 条逐封发送授权，严格 1:1。
- 已有 64 封被邮件服务器接受，2 封保留为真实硬退信，剩余 99 封等待按限速发送；北京时间当天已发 9 封。
- 失败、投递结果不确定和发送中均为 0；IMAP 收件监听健康，连续失败和隔离邮件均为 0。
- 当前处于受控投递恢复：每天最多 10 封、每小时最多 2 封、两封至少间隔 900 秒。3% 硬退信阈值没有提高；最近 50 个真实结果中有 2 个硬退信，恢复授权共 18 个成功样本额度，已经领取 9 个，剩余 9 个。时间窗口重置后自动继续；任何新硬退信都会使旧恢复授权失效。
- 恢复完成后会自动切换到每天最多 50 封、每小时最多 5 封、两封至少间隔 600 秒，不需要再次发送“恢复系统”。
- VPS 每 15 分钟运行一次连续获客调度，始终只保留一个发现任务，按有真实 Campaign 授权且尚未达到目标的 Campaign 轮转；联系人补全、文案生成、逐封授权、发送和 IMAP 监听均可 24 小时持续运行。

这里的“已发送”只表示对方邮件服务器或上游 SMTP 已接受，不等于一定进入收件箱、被阅读或得到回复。

## 平时先看公网监测站，操作仍用飞书

Codex 和服务器命令只用于维护。日常观察请使用公网 HTTPS 监测站。地址、用户名和密码只保存在本机受保护文件中：

```text
C:\path\to\crm-agent\private\dashboard-access.txt
```

公网入口使用有效 TLS 证书和 Basic Auth。未登录访问返回 401，登录后监测页返回 200，未授权的其他服务器路径返回 404。不要把该文件内容、完整网址或口令转发到公开渠道；不再需要为了监测一直开着本机电脑。

监测站现在包含七个视图：总览、邮件中心、来源分析、获客漏斗、任务队列、投递安全和运行参数。页面标题、状态、任务、来源、参数、退信原因和发送阻塞均显示中文。开发信和收到邮件的每一行都可以点击；详情默认显示中文主题、中文正文、客户职业、为什么匹配、推广产品、联系方式获取途径、来源页面和中文证据。英文邮件原文只保留在折叠的“英文审计原文”中，不会修改真实邮件。页面支持搜索，在手机上会自动切换为卡片布局。暂停、恢复、发起获客任务和人工接管等控制仍在飞书机器人里完成。

第一次打开某封尚未翻译的邮件时，页面会短暂显示“正在生成中文译文”。译文由服务器读取数据库中的真实邮件生成，并按原文指纹缓存；再次打开直接显示，不会重复调用模型。若邮件原文变化，旧译文自动失效。公司名、人名、邮箱、网址、WhatsApp、领英和技术型号属于标识，不强行翻译。

回复和询盘统计采用保守口径：只有投递到当前企业邮箱、成功关联到客户和发送线程且被判定为真人回复的邮件才计为业务回复。SQLite 共保留 40 条入站记录，其中当前企业邮箱有 3 条，37 条旧 Gmail/系统收件只保留为历史隔离审计数量，不再进入当前列表或回复率。当前 3 条是 2 封硬退信和 1 封自动回复，确认真人回复、询盘和商机仍为 0。

先发送：

```text
能不能用了
```

或：

```text
状态
```

机器人会直接告诉你：研究是否可用、现在有没有真正可发送的客户邮件、还缺什么。不要只看“线索数量”；只有真实发送门禁全部通过才算可发。

## 当前阶段怎么做

现在不需要重复扫码、配置 DKIM、部署或恢复系统。Agent 正在 VPS 上按受控恢复节奏继续发送，并持续补充客户与消息库存。平时用监测站看运行过程和邮件明细，用飞书处理回复、询价、退信告警和控制命令。大屏关掉、本机断电或 Codex 退出都不会停止 VPS 上的获客、文案、发送和收件监听。

飞书多维表格的容量问题已通过 Events 自动轮换修复，旧表和 52 条历史失败记录均保留。V20 还会合并同一进程中的重复全量同步，并阻止重复分页令牌或超过 100 页的异常分页无限运行。SQLite 仍是权威数据库；不要手工删除旧飞书记录来“腾容量”。

在飞书发送下面的命令可以建立一个 Campaign Brief 草稿：

```text
开发目标市场的经销商20家，产品信息以当前已审核配置为准
```

系统会把国家、产品、买家类型和数量转成正式获客任务，并按下面的完整链路运行。

## 完整链路：从发现客户到发送邮件

1. **确定目标。** 你在飞书说明国家、产品、客户类型和数量。Agent 把它拆成不同语言、不同产品叫法和不同买家角色的搜索组合。
2. **发现候选公司。** 系统通过本地 SearXNG 调用 Mojeek、Presearch、Dogpile 和 Yandex，搜索官网、产品页、方案页、项目/新闻、展会目录、行业目录和公开 LinkedIn 页面。目录和社交页面只用于发现线索，最终必须回到明确的公司官网核实。
3. **判断公司是否相关。** Agent 阅读官网公开内容，确认公司所在市场、主营业务和至少一个与示例制造商产品/应用相关的事实。评分只用于相关性和证据排序，不是“回复概率预测”。
4. **获取联系方式。** 系统优先读取官网首页、Contact、Sales、Export、RFQ、Team 和 Management 页面，从可见文字、`mailto:` 和 Cloudflare 保护邮箱中提取地址，并保存“具体页面、原文片段和提取方法”。系统不凭姓名或域名猜邮箱。
5. **给联系人分级。** A 类是具名、在职、企业同域且由正式验证器判定为 `VALID` 的邮箱；B 类是公司官网同域页面精确公开的销售、出口、询价或通用企业邮箱，并且不能明确无效；C 类是缺少证据、跨域、猜测、临时或无效邮箱，不自动发送。
   当前生产有 218 个带邮箱的联系人，其中 217 个属于有官网精确证据的 B 类企业邮箱；唯一 C 类地址已标记 `INVALID`。这就是当前“降低门槛”的实际范围：不再要求每封都必须是具名 A 类，但仍不向猜测、跨域或明确无效地址发送。
6. **生成开发信。** Agent 只使用客户官网可追溯事实和已经批准的示例制造商产品资料，组合成“客户事实 + 对应产品价值 + 一个明确行动请求”。系统同时加入英文发件身份、公司地址和退订说明，不虚构客户采购意图、案例、认证、性能、价格、交期或多个行动请求。
7. **逐封绑定与授权。** 每个收件人、目标地址、开发信正文、客户证据和卖方资料都会绑定哈希，并生成一条对应的逐封授权。Campaign 的 500 总授权只是最大容量，不代表已经找到或发送 500 封。
8. **发送前最后复核。** Dispatcher 每分钟运行一次，检查全局暂停、逐封授权、DNC、客户是否回复、证据有效期、邮箱状态、IMAP 健康、域名认证、退订信息、发送间隔、小时/每日上限和退信率。全部通过后才领取一封邮件。
9. **真实发送。** Nodemailer 通过企业邮箱 SMTP 提交邮件。只有 SMTP 明确返回接受，数据库才记为 `SENT`；如果连接中断导致结果不确定，邮件会进入隔离状态并暂停全部发送，避免重复发。
10. **监听回复和退信。** IMAP 持续读取新邮件，用 Message-ID 和回复线程关联客户。询价、兴趣或转介绍会立即停止该客户的自动化、创建商机和 15 分钟跟进任务并在飞书提醒；退订写入 DNC；硬退信会把邮箱标为无效；无法判断的真人回复也会保守停止并交给你。

当前 165 封消息已经拥有逐封授权，不需要你逐封点击。DNC、回复即停、无效邮箱、IMAP 健康、限速、退信暂停和退订规则仍然有效。Agent 永远不会自动报价。

## 扩大联系方式和全域获客

当前邮箱主路径是“搜索或目录发现公司，再回到公司官网提取并保存证据”。官网来源包括首页、Contact、Sales、Export、RFQ、Team 等页面上的可见文字、`mailto:` 和 Cloudflare 保护字段；大屏会按来源、渠道和联系方式统计数量与业务结果。

推荐按以下顺序扩展，避免把“来源多”做成“不可追溯的数据堆积”：

1. **海关数据。** 先导入一份脱敏 CSV/XLSX 样本，建立版本化数据集，保留数据供应商、查询条件、进口商/出口商、HS 编码、产品描述、国家、日期、数量/金额和原始行号。它用于判断真实贸易活跃度和公司优先级，联系方式仍要从官方或合规来源单独取证。
2. **高质量公开目录。** 接入官方展会名录、行业协会会员、经销商目录、政府采购/项目公告和企业注册信息。每条发现结果都保留来源链接、抓取时间和原文证据，再回官网核实。
3. **搜索 Provider。** 免费搜索继续保留，同时可增加一个有封顶预算和审计的商业搜索 Provider，提高地区、语言和长尾查询覆盖；按“发现公司率、获得可用联系方式率、回复率、询盘率、成本”比较来源，不按原始结果数量评优。
4. **企业微信。** 个人微信没有适合 VPS 机器人的正式接口。推荐用企业微信群机器人或企业微信应用推送发送量、退信、回复、询盘和异常告警；控制命令仍应做身份和权限校验。
5. **WhatsApp 和社交平台。** 使用 WhatsApp Business Platform、LinkedIn 或其他平台的官方接口、模板、Webhook 和已同意联系的对象。系统可以统一客户、来源和会话时间线，但不应绕过平台限制或自动群发未经同意的私信。

统一数据层建议继续以 SQLite 为当前权威源，把 `公司 -> 联系人 -> 联系点 -> 来源证据 -> 触达 -> 回复 -> 询盘` 串成同一条可追溯时间线。海关数据量和多渠道会话明显增长后，再迁移到 PostgreSQL；不要先用删除历史记录解决容量问题。

## 什么时候需要你接管

飞书收到客户回复或询价告警后，由你在原邮件线程中处理报价和商务谈判。以下情况 Agent 会自动停止并交给你：

- 客户询价、表示兴趣或回复内容无法可靠分类。
- 客户退订、拒绝或要求停止联系。
- 客户发生硬退信。
- 达到每小时或每日限额，或退信率触发暂停。
- 客户进入 `HUMAN_TAKEOVER`。

## 收件监控异常时会发生什么

Agent 不只检查邮箱是否曾经连接成功，还会持续记录最近一次成功收件检查和连续失败次数。如果 IMAP 长时间没有成功，或连续失败达到安全阈值，系统会立即暂停全部外发并发送飞书告警，避免在看不到回复、退订或退信时继续发信。邮箱恢复后系统只提示“收件监控已恢复”，不会自动解除外发暂停。

某一封邮件自身损坏或无法解析时，系统按 UID 单独重试。达到上限后只隔离这一封，并继续处理后面的回复。飞书隔离卡可请求重新处理；如果邮箱的 UIDVALIDITY 已变化，系统会明确拒绝重放且不会回退收件游标。隔离记录只保存定位、哈希、大小、错误摘要和脱敏预览，不复制整封邮件原文。

## 看效果看什么

监测站适合持续观察实时过程和单封邮件详情；发送 `今日漏斗` 可查看当天结果，发送 `漏斗报告` 可查看全量结果。主要关注：具名在职联系人、独立 `VALID` 邮箱、SMTP 接受、实际送达、正面回复、P1/P2 询价、报价、成交收入和毛利。未送达或未关联的记录不能冒充业务结果。
